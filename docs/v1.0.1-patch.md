# v1.0.1 recovery-state patch — Phase 0A.4

Prepared locally for review; not committed, tagged, released or deployed. The defects were discovered during product-video claim review. No video implementation is part of this patch.

## Correction

- Error Intake and Human Approval's RECOVERED switch rules compared against `R`, while verification and recovered builders use `RECOVERED`. The rules now match that contract.
- Verify Recovery's loop guard previously converted canceled/crashed terminal escalation into recovery-pending state when budget remained. It now preserves terminal `RETRY_FAILED` escalation and fails unexpected retry-failure state closed.
- Both parent retry-failed builders preserve the verification status and human-attention flag. Escalated failures propose no retry; ordinary recovery-pending failures retain the RETRY proposal.
- Retry-failed events derive `new_status` from the incident update and describe recovery-pending or terminal escalation accurately, without claiming another retry automatically runs.
- Pending verification persists `VERIFYING`, human attention and no continuation; parent builders reject missing attention rather than silently clearing it.

The user corrected the published local workflows manually. Phase 0A.4 inspected them read-only and synchronized only the affected code/rule fields into three sanitized exports. Credentials remain removed, API origins remain reserved placeholders, subworkflow mappings remain `IMPORT_*`, and imports remain inactive. Node IDs/names, graph connections, expressions and unaffected code are unchanged.

`loop_required` is state metadata only. Retry-failed and pending branches end at event persistence; no automatic retry continuation, scheduler or poller was introduced. AI authority, deterministic recovery policy, retry budget limits, retry safety, human-approval semantics and credentials are unchanged. No operational incidents or event rows were modified by this work.

## Regression verification

Run `npm run test:workflows`. It uses Node's built-in test runner and isolated VM execution of pure code nodes with fixed synthetic time and mocked node inputs. It makes no network calls, has no credentials, does not execute n8n workflows and does not write incident/event data.

| Success | RECOVERED | RECOVERED | false | false |

The suite also checks unexpected retry-failure state, invalid budgets, builder rejection, event-state fidelity, all four parent routes and event-persistence paths, and absence of automatic continuation/scheduling triggers. It fails if a recovered router returns to `R`. Ten tests pass against both inspected published code and synchronized exports. This fast, deterministic check is appended to `verify:local` without removing existing steps.
